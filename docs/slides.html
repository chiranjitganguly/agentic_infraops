Middle Layer

7 MCP Servers — The Integration Layer

MCP servers are lightweight FastAPI services wrapping external systems. Agents call them as tools over HTTP/SSE. No agent talks to external systems directly.

:8089

mcp-postgres

All DB operations — jobs, requests, users, audit, rate limits, password/API-key verification.

:8091

mcp-pubsub

Publish to 3 topics: provisioning requests, status events, audit events. Supports local emulator.

:8090

mcp-gcp-resource

Compute, Storage, VPC API wrappers. All calls go through circuit breaker (opens after 5 failures). Supports dry_run.

:8093

mcp-knowledge-base

Qdrant hybrid search (BM25 + 1536D dense vectors). Index / search / stats tools.

:8094

mcp-airflow

Trigger DAG runs, get run status, list recent runs. Used by provisioning-agent to kick off provision_vm_dag.

:8096

mcp-backstage

Register / update / query Backstage catalog entities. Every provisioned resource must be registered (ADR-0005).

:8095

mcp-gmail

Poll unread messages, send/reply emails, detect auto-replies. Powers email-channel request flow.

Pattern: Agent → Skill → MCP Server → External System

No agent talks to GCP, Postgres, or any external system directly. All communication goes through the MCP layer, giving you a single place to instrument, rate-limit, and circuit-break external calls.

Retry Policy

3 retries, exponential backoff: max(30, 2ⁿ×30 ± jitter) — max 300s delay per retry.

Database Writes

All status updates via raw psycopg2. Every UPDATE OF status fires pg_notify → SSE stream.

Rollback Strategy (ADR-0006)

rollback_resources appended after each successful GCP create — never pre-populated. Deletes exactly what was created.

Backstage (ADR-0005)

Backstage failure triggers full rollback when BACKSTAGE_REQUIRED=true. Every resource must be catalogued.

09
Real-Time Updates

PostgreSQL NOTIFY → Browser (No Polling)

1

Airflow DAG writes status
psycopg2 UPDATE provisioning_jobs SET status='in_progress'

2

PostgreSQL trigger fires automatically
pg_notify('infraops_job_status', '{"job_id":"...","status":"in_progress"}')

3

Web Backend asyncpg listener receives NOTIFY
Filters to the specific job_id, emits SSE event over open connection.

4

Browser EventSource receives event
useJobStream hook updates Zustand store → JobStatusTimeline re-renders.

5

Terminal status closes stream
completed | succeeded | failed | rolled_back | cancelled → SSE sends event: done → connection closed.

Race Condition Prevention

On SSE connect, the backend immediately fetches and emits the current status from DB before subscribing to NOTIFY. This prevents a missed event if the job completed between the confirm POST and the stream GET.

SSE Trigger SQL

CREATE TRIGGER job_status_notify
AFTER UPDATE OF status
ON provisioning_jobs
FOR EACH ROW EXECUTE FUNCTION
notify_job_status_change();

-- Fires:
pg_notify('infraops_job_status',
json_build_object(
'job_id', NEW.id::text,
'status', NEW.status::text
)
)

Terminal Statuses (close stream)

succeeded completed failed rolled_back cancelled

Data Model

State Machines

InfraRequest
received └→ classifying └→ clarifying (max 2 rounds) └→ awaiting_confirmation │ ├→ confirmed → fulfilled │ ├→ expired (20 min timeout) └→ cancelled rejected ← confidence < 0.55 (email) failed ← downstream failure
ProvisioningJob (ADR-0004)
awaiting_confirmation │ (user cancel → cancelled) └→ queued │ (user cancel → cancelled) └→ in_progress └→ retrying (≤3 retries) │ ├→ succeeded ✓ └→ rollback_started └→ failed ✗ Auto-expires from awaiting_confirmation after 20 min.

Idempotency key: SHA256(resource_type:resource_name:region) — duplicate submissions return existing job, never create a second.

Only Airflow writes terminal states (succeeded, failed) — eliminates dual-write race conditions (ADR-0003).

Auth, Guardrails & Controls

Authentication — Two Methods

JWT Bearer

Login via POST /auth/login → HS256 token, 8-hour expiry. Browser sessions.

X-API-Key

bcrypt hash in DB, 90-day expiry. Service-to-service / CLI access.

Brute-Force Protection

5 failed auth attempts per IP in 60 seconds → 429 Too Many Requests.

🔒 bcrypt (12 rounds) — passwords + API keys never stored plaintext

🔑 JWT 8-hour expiry — invalidated on logout

📋 Full audit trail — all actions logged with actor + correlation_id

🚫 Auto-redaction — api_key, password, token removed from logs + audit

Architecture Principles

7 Key Design Patterns

Pattern 1

Protocol-Based DI

Skills accept GcpClient(Protocol) and PostgresClient(Protocol) — inject mocks in tests, real clients in prod.

Pattern 2

Correlation Context Propagation

correlation_id + request_id thread through A2A calls, PubSub events, DB rows, and log lines. End-to-end traceability.

Pattern 3

Idempotency via SHA256 Keys

SHA256(type:name:region) — duplicate submissions always return the existing job, never create a second resource.

Pattern 4

Two-Phase Confirmation

All destructive ops: Phase 1 (summary + 20-min window) → Phase 2 (explicit confirm → queue → execute). Natural audit point.

Pattern 5

Append-Only Rollback Resources

Rollback list populated after each successful GCP create call — deletes exactly what exists, no phantom deletes.

Pattern 6

NOTIFY / LISTEN (no polling)

DB trigger → pg_notify → asyncpg listener → SSE → browser. Zero-latency status updates without any polling loop.

Pattern 7

Thin Agents, Thin DAGs

Neither agents nor DAG tasks contain business logic. All logic in business_logic. Reusable, independently testable.

Architecture

Architectural Decision Records

ADR-0001

Skills as Business Logic Layer

Agent → Skill → MCP → External. Skills are reusable across agents and DAGs, testable in isolation. Agents and DAGs are thin wrappers.

ADR-0002

Single Resource Per Request

"Provision two VMs" is rejected. One request = one resource. Makes idempotency keys unambiguous and confirmation UX clear.

ADR-0003

Airflow DAG Owns Job State

Only the DAG writes terminal states. Eliminates dual-write races between the agent and notification service.

ADR-0004

Two-Phase Provisioning State

awaiting_confirmation (times out, user can cancel) → queued (persists until Airflow picks up, user can cancel) → in_progress (no cancel). Clear semantic separation.

ADR-0005

Backstage = Hard Requirement

Backstage failure after GCP create → rollback. Keeps catalog consistent with GCP. BACKSTAGE_REQUIRED=false for local dev.

ADR-0006

Rollback Resources Appended After Create

rollback_resources populated only after a successful GCP create. Never pre-populated. Deletes only what actually exists — no spurious 404s.

agents/orchestrator/agent.py

Purpose

Orchestrator Agent — classifies intent via LiteLLM, enforces developer guardrails and rate limits, routes to provisioning / enquiry / FAQ sub-agents via ADK A2A HTTP. Stateless; all state in PostgreSQL. Exposes root_agent for ADK AgentLoader discovery. Served via get_fast_api_app(a2a=True) on port 8001.

Key Imports
  • → BaseAgent (google.adk)
  • → validate_provisioning_guardrails
  • → classify (intent_classification skill)
  • → OrchestratorInput/Output (contracts)
  • → DeveloperGuardrails
_default_guardrails() → DeveloperGuardrails

Reads ALLOWED_REGIONS, ALLOWED_MACHINE_TYPES, ALLOWED_STORAGE_CLASSES, DEVELOPER_DAILY_LIMIT from env vars (comma-separated). Returns a DeveloperGuardrails dataclass with those values. Called when no guardrails are injected.

_app_name_from_url(agent_url: str) → str

Parses URL hostname via urlparse, strips "-agent" suffix and replaces "-" with "_". e.g. http://provisioning-agent:8002 → "provisioning". Used to build the ADK appName for session and /run endpoints.

async _call_sub_agent(agent_url, task_data) → dict

ADK A2A client. Creates a session via POST /apps/{app}/users/orchestrator/sessions/{uuid}, then calls POST /run with the task payload. Parses the returned events list in reverse order, extracts the first JSON text part, and returns the parsed dict. Uses inject_correlation_headers for distributed tracing.

async route(*, input, postgres, provisioning_agent, enquiry_agent, faq_agent, classifier, guardrails) → OrchestratorOutput

Core business logic (injectable for testing). Steps: (1) classify intent; (2) confidence < 0.55 → clarification_needed (web) or rejected (email); (3) provision + developer → validate_provisioning_guardrails; (4) guardrail fail → guardrail_violation; (5) provision + developer → increment_daily_usage, limit_reached → rate_limited; (6) check missing required fields for provision; (7) call correct sub-agent; (8) return OrchestratorOutput(outcome=routed).

_DefaultClassifier.classify(raw_input, channel) → ClassificationResult

Thin Protocol adapter. Delegates to business_logic.intent_classification.classifier.classify(raw_input, channel) which calls LiteLLM with a structured-output prompt. Returns {intent, confidence, normalized}.

_DefaultPostgresClient.increment_daily_usage(requesting_user, daily_limit) → dict

Calls mcp_servers.postgres.server.increment_daily_usage directly (module import, not HTTP). Returns {"count": int, "limit_reached": bool}.

_DefaultPostgresClient.get_user_role(user_id) → dict

Stub — returns empty dict. User role is propagated from web-backend via OrchestratorInput.user_role, not re-fetched by the agent.

_A2AClient.__init__(url: str)

Stores the sub-agent base URL. One instance per sub-agent, created inside _run_async_impl.

_A2AClient.submit(**kwargs) → dict

Serialises kwargs (converting dataclasses with dataclasses.asdict), wraps in an A2A envelope {id, message: {role, parts: [{type:data, data:{...}}]}}, and delegates to _call_sub_agent. The sub-agent unpacks this envelope in its own _run_async_impl.

OrchestratorAgent._run_async_impl(ctx: InvocationContext) → AsyncGenerator[Event, None]

ADK entry point. Extracts user_text from ctx.user_content.parts[0].text, parses as OrchestratorInput. Sets CorrelationContext. Calls route() with real client instances. Logs outcome. Yields a single Event whose content.parts[0].text = output.model_dump_json().

agents/provisioning/agent.py

Purpose

Stateless provisioning agent implementing two-phase idempotent job creation. Phase 1 (confirmed=False): SHA256 idempotency check → create DB records → return confirmation summary with 20-min expiry. Phase 2 (confirmed=True): update status queued → publish PubSub → trigger Airflow DAG. Exposes root_agent on port 8002.

Protocols
  • → PostgresClient (6 methods)
  • → PubSubClient.publish_provisioning_request
  • → AirflowClient.trigger_dag_run
_make_idempotency_key(resource_type, resource_name, region) → str

Returns hashlib.sha256(f"{resource_type}:{resource_name}:{region}".encode()).hexdigest(). Used as a UNIQUE DB constraint to prevent duplicate resource creation when the same request is submitted multiple times.

_params_to_dict(inp: ProvisioningInput) → tuple[TypedParams, dict]

Instantiates the correct typed parameters class (VMParameters / BucketParameters / VPCParameters) from inp.parameters dict. Tracks which fields were filled with defaults (machine_type, disk_size_gb, image_family, storage_class) so they can be shown in the confirmation summary. Returns (typed_params, defaults_applied_dict).

async handle_task(inp, postgres, pubsub, airflow) → ConfirmationOutput | QueuedOutput

Phase 1: calls get_provisioning_job_by_idempotency_key; if active job exists rebuilds summary and returns it. Otherwise: _params_to_dict → build_confirmation_summary → create_infra_request → create_provisioning_job(awaiting_confirmation) → return ProvisioningConfirmationOutput with expires_at=now+20min. Phase 2: update_request_status(confirmed) → update_job_status(queued) → publish_provisioning_request → on failure rolls back to awaiting_confirmation → trigger_dag_run (non-fatal if Airflow down) → emit_audit_event(request_confirmed) → return ProvisioningQueuedOutput.

_DefaultPostgresClient (6 adapter methods)

Each method calls the corresponding mcp_servers.postgres.server function directly via module import: get_provisioning_job_by_idempotency_key, create_infra_request, create_provisioning_job, update_job_status, update_request_status, create_audit_event.

_DefaultPubSubClient.publish_provisioning_request(event) → dict

Calls mcp_servers.pubsub.server.publish_provisioning_request(event) directly. Validates schema_version=1.0.0, publishes to infraops.provisioning.requests topic.

_DefaultAirflowClient.trigger_dag_run(dag_id, conf) → dict

Calls mcp_servers.airflow.server.trigger_dag_run(dag_id, conf) directly. Returns {dag_run_id, state}. Failure is non-fatal — logged as warning since PubSub message already published.

ProvisioningAgent._run_async_impl(ctx) → AsyncGenerator[Event, None]

Parses JSON from ctx.user_content.parts[0].text as ProvisioningInput. Propagates existing correlation IDs (not new). Calls handle_task with real client instances. On ValueError yields error Event. On success yields Event with output.model_dump_json().

web/backend/routers/sse.py

Purpose

SSE router: GET /jobs/{job_id}/stream streams provisioning job status changes to the browser using asyncpg LISTEN/NOTIFY. Race-condition fix: emits the current DB status immediately on connect before subscribing to NOTIFY, preventing missed updates if the job completed between confirm POST and stream GET.

Terminal statuses
completed succeeded failed rolled_back cancelled
_AsyncpgListener.listen(channel: str) → AsyncIterator[str]

Creates a dedicated asyncpg connection (not from pool). Creates an asyncio.Queue. Registers an _on_notify callback that calls queue.put_nowait(payload) when a NOTIFY arrives on the channel. Loops with asyncio.wait_for(queue.get(), timeout=30.0) yielding each payload. TimeoutError causes a clean return (keepalive). Finally removes listener and closes connection.

async _fetch_current_status(job_id: str, dsn: str) → str | None

Opens a fresh asyncpg connection, executes SELECT status::text FROM provisioning_jobs WHERE id = $1::uuid, closes the connection. Returns the status string or None if the job doesn't exist. Called once at SSE connect time before subscribing to NOTIFY.

async job_status_stream(job_id, db_listener, dsn) → AsyncIterator[dict]

Generator. Step 1: calls _fetch_current_status and immediately yields a {event:"status", data:JSON} event. If current status is terminal, yields {event:"done"} and returns. Step 2: iterates db_listener.listen("infraops_job_status"), filters by data["job_id"] == str(job_id), yields status events, yields done and returns on terminal status.

async stream_job_status(job_id: UUID, request: Request) → EventSourceResponse

Route handler GET /jobs/{job_id}/stream. Reads DATABASE_URL from env. Creates _AsyncpgListener. Defines event_generator that calls request.is_disconnected() before each yield. Returns sse_starlette.EventSourceResponse wrapping the generator. Client receives text/event-stream with "event:" and "data:" lines.
